# 대화 프롬프트 설계 (볼트 → LLM 다리 🌉)

> **이 게임 대화 품질의 핵심 문서.** 볼트의 설계가 실제 LLM 대화로 바뀌는 지점.
> 관련: [[조건-시스템]] · [[세계관]] · [[지은]]
> 코드: 프롬프트 빌더 `src/utils/helpers.js` `buildSys()` / 호출 `src/utils/ai.js` `callGroq()` / 모델 `llama-3.3-70b-versatile`

## 0. 큰 원칙
대화는 **Groq LLM이 실시간 생성**. 우리가 통제하는 레버는 **시스템 프롬프트(buildSys) 한 개**. 그래서:
> **볼트의 모든 캐릭터/스테이지 글은 "결국 buildSys 슬롯에 들어간다"는 걸 전제로 쓴다.**
> 학습(fine-tune) 안 함 — 프롬프트 엔지니어링 + 정확한 맥락 + 가드레일로 승부.

## 1. 현재 프롬프트 해부 (buildSys)
이미 있는 슬롯:
- 한국어 강제 / [게임 설정] 준모 / [현재 상황] 스테이지·장소·분위기·관계
- [캐릭터] job·mbti·personality·fav·weakness ← **얇음**
- [준모 상태] 말주변/외모/유머
- [반응 기준] 호감도 증감 규칙
- [말투 예시] good/bad few-shot ← **빈약**
- [출력 형식] (장면) / 대사 / 준모 속마음 / [호감도][스탯]

## 2. 진단된 결함 → 볼트가 고칠 것
| # | 결함 | 원인 | 볼트가 공급할 것 |
|---|---|---|---|
| ① | 캐릭터 얇음 | personality 한 줄 | [[캐릭터]]의 욕망/두려움/방어/목소리 → `[캐릭터]` 확장 |
| ② | **장소 틀림** 🔴 | `partners.js.stages`가 옛 기획(미술관 등) | [[02_스테이지]] 정본 장소 → `sl.loc/desc` 교정 |
| ③ | 스테 감정 없음 | 현재 연기지시 슬롯 자체가 없음 | 스테이지 노트 "정서 곡선" → **신설 `[현재 장면 연기 지시]`** |
| ④ | 말투 빈약 | PARTNER_VOICE good/bad 1개 | 캐릭터/스테별 풍부한 few-shot |

## 3. 목표 프롬프트 (개선안 슬롯)
```
... (한국어 강제 / 게임 설정 / 현재 상황) ...

[캐릭터: {이름}]            ← 볼트 캐릭터 바이블에서 컴파일
핵심: {욕망/필요/두려움/방어기제 1~2줄}
목소리: {말투·리듬·침묵 사용}
통하는 것 / 식는 것: {fav / weakness 구체화}

[현재 장면 연기 지시]        ← ★신설, 볼트 스테이지 노트에서
지금 {이름}은: {이 스테의 감정상태/정서곡선 핵심}
이렇게 행동/말함: {이 스테 한정 톤}

[말투 예시]                 ← 캐릭터+스테 맞춤 few-shot (good/bad)
...

(반응 기준 / 출력 형식은 유지)
```

## 4. 컴파일러 (볼트 → 프롬프트) 구현 방향
- **데이터화**: 볼트 핵심을 코드가 읽을 구조로. 두 갈래 중 택1(추후 결정)
  - (a) `partners.js`/`scenes`에 필드 추가 (personality 확장 + 스테별 `mood/actingNote`)
  - (b) 캐릭터/스테 설정을 별도 JSON(`src/data/persona/*.json`)으로 두고 buildSys가 조립
- **buildSys 개조**: 위 [캐릭터]/[현재 장면 연기 지시]/[말투] 슬롯을 새 데이터로 채움.
- **선행 버그 교정**: `partners.js.stages` 장소를 [[02_스테이지]] 정본으로 (②) — 이건 "대화 품질 직결"이라 후순위 버그 아님.

## 5. 나머지 기둥 (프롬프트 밖)
- **기억/상태**: `callGroq`에 넘기는 history + 호감도/플래그를 더 잘 주입 → [[조건-시스템]]
- **가드레일**: OOC/영어 튀어나옴/형식 깨짐 방지 문구 + 거절 톤.
- **모델·파라미터**: temperature/max_tokens, 필요시 모델 교체 검토.
- **평가 루프**: 나쁜 대화 샘플 모아 → 프롬프트 개선 반복(테스트셋).

## 6. 작업 순서 (제안)
1. 볼트 캐릭터 3인 + 스테이지 노트를 **"슬롯에 넣을 수 있는 형태"**로 완성
2. 데이터화 방식(4-a/b) 결정 → `buildSys` 개조 + 장소 버그 교정
3. 기억/가드레일 보강
4. 실제 플레이로 평가 → 반복
